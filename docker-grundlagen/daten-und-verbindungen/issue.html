Daten überleben lassen und Container verbinden

Als Entwicklerin möchte ich, dass die Daten meiner Datenbank den Container überleben und meine Anwendung die Datenbank über ihren Namen erreicht, damit ich Container ersetzen kann, ohne etwas zu verlieren.

Lernziele

Du…

  • legst ein Volume an und hängst es an die Stelle im Container, an der die Anwendung ihre Daten ablegt.
  • weist nach, dass Daten in einem Volume das Löschen des Containers überleben.
  • unterscheidest Volume und Bind Mount und begründest, wann Du welches nimmst.
  • legst ein eigenes Netzwerk an und sprichst einen Container von einem anderen aus über seinen Namen an.
  • begründest, warum Du dafür keinen veröffentlichten Port brauchst.

Definition of Done

  • Ein Volume db-daten existiert und ist an den Datenverzeichnis-Pfad des PostgreSQL-Containers gehängt.
  • Du hast eine Tabelle mit Daten angelegt, den Container gelöscht, einen neuen erzeugt – und die Daten sind noch da.
  • Ein Netzwerk kursnetz existiert, und der Datenbank-Container steht darin.
  • Aus einem zweiten Container heraus erreichst Du die Datenbank über den Namen meine-db, ohne dass ein Port veröffentlicht ist.
  • Du hast Deine eigene Seite per Bind Mount in einen NGINX-Container gehängt und im laufenden Betrieb geändert.
  • Du hast die Reflexionsfragen schriftlich beantwortet.

Arbeitsschritte

Aufräumen, was von gestern übrig ist

docker container stop meine-db meine-db-test

docker container rm meine-db meine-db-test

Hinweis: Stört sich Docker an einem Namen, der nicht existiert, ist das in Ordnung – dann war der Container schon weg.

Ein Volume anlegen

docker volume create db-daten

docker volume ls

Die Datenbank mit Volume starten

PostgreSQL legt seine Daten unter /var/lib/postgresql/data ab. Genau dorthin hängst Du das Volume.

docker container create --name meine-db -v db-daten:/var/lib/postgresql/data -e POSTGRES_DB=helloworld -e POSTGRES_USER=kurs -e POSTGRES_PASSWORD=geheim postgres:18

docker container start meine-db

Daten anlegen

docker container exec meine-db psql -U kurs -d helloworld -c "CREATE TABLE gruss (id SERIAL PRIMARY KEY, text TEXT NOT NULL)"

docker container exec meine-db psql -U kurs -d helloworld -c "INSERT INTO gruss (text) VALUES ('Hallo Welt'), ('Hello World')"

docker container exec meine-db psql -U kurs -d helloworld -c "SELECT * FROM gruss"

Den Container löschen – und vorher eine Vorhersage aufschreiben

Schreib auf, was Du erwartest. Dann führ die Befehle aus.

docker container stop meine-db

docker container rm meine-db

docker container create --name meine-db -v db-daten:/var/lib/postgresql/data -e POSTGRES_DB=helloworld -e POSTGRES_USER=kurs -e POSTGRES_PASSWORD=geheim postgres:18

docker container start meine-db

docker container exec meine-db psql -U kurs -d helloworld -c "SELECT * FROM gruss"

Hinweis: Vergleich das Ergebnis mit dem von gestern. Derselbe Ablauf, anderes Ergebnis – der einzige Unterschied ist das -v.

Ein eigenes Netzwerk anlegen

docker network create kursnetz

docker network ls

Häng den laufenden Datenbank-Container in das Netzwerk:

docker network connect kursnetz meine-db

Die Datenbank von einem anderen Container aus erreichen

Starte einen kurzlebigen zweiten Container im selben Netzwerk und sprich die Datenbank über ihren Namen an.

docker run --rm --network kursnetz -e PGPASSWORD=geheim postgres:18 psql -h meine-db -U kurs -d helloworld -c "SELECT * FROM gruss"

Hinweis: Beachte, was hier nicht steht: keine IP-Adresse und kein -p. Woher weiß der zweite Container, wo meine-db liegt?

Probier zum Vergleich dasselbe ohne das Netzwerk:

docker run --rm -e PGPASSWORD=geheim postgres:18 psql -h meine-db -U kurs -d helloworld -c "SELECT 1"

Hinweis: Lies die Fehlermeldung genau. Sie sagt Dir, was ohne eigenes Netzwerk fehlt.

Einen Bind Mount ausprobieren

Wechsle in Dein Website-Verzeichnis von gestern und häng es direkt in einen NGINX-Container.

cd ~/meine-website

docker run -d --name live-website -p 8080:80 -v "$PWD":/usr/share/nginx/html:ro nginx:1.27.5

curl http://localhost:8080

Ändere jetzt die Datei – ohne irgendetwas neu zu bauen oder neu zu starten:

echo "<h1>Im laufenden Betrieb geaendert</h1>" > index.html

curl http://localhost:8080

Hinweis: Das :ro am Ende bedeutet „nur lesen“. Überleg Dir, warum das für einen Webserver eine gute Idee ist.

Aufräumen – aber das Volume behalten

docker container stop live-website

docker container rm live-website

Hinweis: Lass meine-db, db-daten und kursnetz stehen. Du brauchst sie in der nächsten Übung.

Reflexionsfragen

  • Die Daten haben das Löschen des Containers überlebt. Wo lagen sie, und wem gehören sie?
  • Ist ein Volume nicht das Gegenteil von Zustandslosigkeit? Formuliere Deine Antwort in einem Satz.
  • Wann würdest Du ein Volume nehmen und wann einen Bind Mount? Nenne für beides ein Beispiel aus Deinem eigenen Projekt.
  • Warum hat der Name meine-db erst im eigenen Netzwerk funktioniert?
  • Brauchtest Du für die Verbindung zwischen den beiden Containern ein -p? Wofür ist -p dann da?
  • Was spricht dagegen, die Anwendung und ihre Datenbank in einen Container zu packen?
