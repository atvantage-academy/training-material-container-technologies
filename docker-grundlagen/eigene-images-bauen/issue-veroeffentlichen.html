Ein Image versioniert in eine Registry pushen

Als Entwickler möchte ich mein Image an einem Ort ablegen, an den andere herankommen, damit nicht jeder es selbst bauen muss – und damit später nachvollziehbar bleibt, welche Fassung wo lief.

Lernziele

Du…

  • meldest Dich an einer Registry an und legst dort ein Repository an.
  • veröffentlichst ein Image in der Registry.
  • begründest, warum ein Verlass auf latest ein Zurückrollen unmöglich macht.

Definition of Done

  • Du bist an der Registry angemeldet und hast dort ein Repository meine-website angelegt.
  • Dein Image liegt in der Registry unter dem Tag 1.0.0.
  • Eine zweite Fassung liegt als 1.0.1 in der Registry, und latest zeigt auf sie.
  • Du hast die Reflexionsfragen schriftlich beantwortet.

Arbeitsschritte

Ein Repository anlegen und sich anmelden

Images liegen in der Registry unter einer Organisation. Leg Dir eine an – oder nimm Deinen eigenen Kontonamen, wenn Deine Registry ihn als Organisation führt. Darin legst Du ein Repository namens meine-website an; beides geht über die Weboberfläche der Registry.

Melde Dich anschließend auf der Kommandozeile an:

docker login <registry>

Hinweis: <registry> ist die Adresse Deiner Registry, etwa registry.example.com. Für Docker Hub lässt sich der Parameter weglassen – das ist die Vorgabe.

Nutzt Dein Konto eine zweistufige Anmeldung, brauchst Du hier ein Zugriffstoken statt Deines Passworts. Das legst Du in den Einstellungen Deines Registry-Kontos an.

Dem Image den Namen seines Ziels geben

Ein Image muss so heißen wie der Ort, an den es soll. Ersetze <deine-org> durch den Namen Deiner Organisation. Bei einer anderen Registry als Docker Hub gehört auch deren Adresse mit in den Namen.

docker image tag meine-website:1.0.0 <deine-org>/meine-website:1.0.0

docker image ls

Hinweis: Vergleiche die Spalte IMAGE ID der beiden Zeilen. Wie viele Images hast Du jetzt – und wie viele Namen?

Diesen Schritt kannst Du Dir künftig sparen: docker image build nimmt mehrere -t entgegen und vergibt beide Namen gleich beim Bauen – docker image build -t meine-website:1.0.0 -t <deine-org>/meine-website:1.0.0 .

Das Image veröffentlichen

docker image push <deine-org>/meine-website:1.0.0

Sieh in der Weboberfläche der Registry nach, ob Dein Image angekommen ist.

Einen beweglichen Zeiger daneben setzen

docker image tag meine-website:1.0.0 <deine-org>/meine-website:latest

docker image push <deine-org>/meine-website:latest

Hinweis: Dieser Push war deutlich schneller als der erste. Überleg Dir, warum – die Antwort hat mit den Layern eines Images zu tun.

Eine zweite Fassung veröffentlichen

Ändere Deine Seite und bau eine neue Version:

echo "<h1>Meine Seite, dritte Fassung</h1>" > index.html

docker image build -t <deine-org>/meine-website:1.0.1 .

docker image push <deine-org>/meine-website:1.0.1

Zieh jetzt den beweglichen Zeiger nach:

docker image tag <deine-org>/meine-website:1.0.1 <deine-org>/meine-website:latest

docker image push <deine-org>/meine-website:latest

Hinweis: Sieh Dir in der Registry an, welche Tags jetzt auf welchem Stand liegen. Und dann die Frage, auf die es ankommt: Wenn jemand gestern <deine-org>/meine-website:latest gezogen hat – welche Fassung hat er bekommen? Und wie fändest Du das heute noch heraus?

Optional: Das Image zurückholen

Lösch Deine lokalen Kopien und hol Dir die veröffentlichte Fassung:

docker image rm <deine-org>/meine-website:1.0.0

docker image rm <deine-org>/meine-website:latest

docker image pull <deine-org>/meine-website:1.0.0

docker image ls

Reflexionsfragen

  • Wie weist Du einem bereits gepushten Image zusätzlich das Tag latest zu? Musst Du es dafür neu bauen?
  • Welche Schritte führst Du aus, um eine Änderung als Version 1.0.1 zu veröffentlichen und latest mitzuziehen?
  • Was passiert, wenn Du ein Image nur mit dem Tag latest pushst und dieses Tag bei jeder Änderung verschiebst?
  • Warum war der zweite Push so viel schneller als der erste?
  • Was passiert, wenn Du im Dockerfile bei FROM das Tag weglässt? Warum ist das für einen Build, den jemand in einem halben Jahr wiederholt, ein Problem?
