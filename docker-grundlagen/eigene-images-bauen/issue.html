    Ein eigenes Image bauen

    Als Entwicklerin möchte ich meine eigenen Inhalte in ein Image bringen, damit ich sie weitergeben kann, ohne zu erklären, wie man sie installiert.

    Lernziele

    • Du schreibst ein Dockerfile und baust daraus ein eigenes Image.
    • Du erklärst, welche Anweisungen beim Bauen des Images und welche beim Starten des Containers ausgeführt werden.

    Definition of Done

    • Du hast ein eigenes NGINX-Image mit Deinen eigenen Webseiten.
    • Mindestens ein Container daraus läuft bei Dir.
    • Du hast die Kontrollfragen beantwortet

    Arbeitsschritte

    Die Seite hast Du schon. In der ersten Übung, Einen Container aus einem fremden Image betreiben, liegt in Deinem Verzeichnis website eine index.html – damals hat der Container sie von außen eingehängt bekommen. Nimm sie als Vorlage; diesmal wandert sie ins Image. Wer sie nicht mehr hat, schreibt in zwei Minuten eine neue.

    Das Dockerfile schreiben

    Welche Anweisungen ein Dockerfile kennt und was sie tun, steht in der Dockerfile Reference. Schlag dort nach – das ist Teil der Aufgabe.

    Dein Dockerfile soll

    • auf dem Image nginx:1.27.5 aufsetzen,
    • Deine index.html dorthin kopieren, wo NGINX seine Seiten sucht (/usr/share/nginx/html),
    • beim Bauen eine zweite Seite erzeugen, die es vorher nicht gab,
    • den Port nennen, auf dem der Webserver im Container lauscht.

    Die Datei heißt genau Dockerfile, ohne Endung, und liegt neben Deiner index.html.

    Ein fertiges Dockerfile ansehen 
    FROM nginx:1.27.5
COPY index.html /usr/share/nginx/html/index.html
RUN echo "<h1>Beim Bauen entstanden</h1>" > /usr/share/nginx/html/gebaut.html
EXPOSE 80

    Überleg Dir, bevor Du weitermachst: Welche dieser Zeilen läuft beim Bauen, welche beim Starten?

    Ohne Namen bauen und nachsehen

    docker image build .

    docker image ls

    Hinweis: Der Punkt am Ende ist das Verzeichnis, das an den Docker-Dienst geschickt wird. Steh in Deiner Shell in dem Verzeichnis, in dem das Dockerfile liegt – sonst findet der Bau es nicht. Und alles, was dort liegt, geht mit: Leg nichts ab, was nicht ins Image soll.

    Findest Du Dein Image in der Liste wieder? Sieh genau hin – und wenn Du es nicht findest, such mit docker image ls --filter dangling=true weiter. Genau das ist der Grund, warum der nächste Schritt anders aussieht.

    Mit Namen und Version bauen

    docker image build -t meine-website:1.0.0 .

    docker image ls

    Einen Container starten und beide Seiten abrufen

    Erzeuge aus Deinem Image einen Container, gib den Port nach außen und starte ihn. Ruf dann beide Seiten ab: Deine eigene und die, die beim Bauen entstanden ist.

    Zum Schluss aufräumen: Stopp den Container und lösch ihn. Das Verzeichnis mit Dockerfile und index.html bleibt stehen – Du brauchst es in den nächsten beiden Übungen wieder.

    Reflexionsfragen

    • Was passiert, wenn Du beim Bauen des Images den Parameter -t weglässt? Wie findest Du so ein Image später wieder?
    • Du änderst den Inhalt Deiner index.html. Welche Schritte brauchst Du, bis die neue Fassung per HTTP zu sehen ist? Zähl sie der Reihe nach auf – und vergleich das mit dem dritten Container aus der ersten Übung.
    • Wofür wird EXPOSE im Dockerfile verwendet?
    • Was ist der Unterschied zwischen ENTRYPOINT, CMD und RUN? Welche davon laufen beim Bauen, welche beim Starten?
    • Wofür kann man HEALTHCHECK verwenden? Warum reicht „der Prozess läuft“ nicht als Aussage?
