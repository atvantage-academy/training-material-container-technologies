Ein eigenes Image aus einem Dockerfile bauen

Als Entwicklerin möchte ich meine eigenen Inhalte in ein Image bringen, damit ich sie weitergeben kann, ohne zu erklären, wie man sie installiert.

Lernziele

Du…

  • schreibst ein Dockerfile, das auf einem fremden Image aufsetzt und eigene Dateien hineinkopiert.
  • baust daraus ein Image mit einem Namen und einer Version und erklärst, was ohne -t passiert.
  • unterscheidest an Deinem eigenen Dockerfile, welche Anweisungen beim Bauen und welche beim Starten laufen.
  • ordnest die Anweisungen so, dass der Build-Cache trägt, und weist den Effekt nach.

Definition of Done

  • In Deinem Arbeitsverzeichnis liegt ein Dockerfile und eine eigene HTML-Datei.
  • Du hast einmal ohne und einmal mit -t gebaut und den Unterschied in docker images gesehen.
  • Ein Container aus Deinem Image meine-website:1.0.0 läuft und liefert Deine Seite aus.
  • Die zweite Seite, die beim Bauen per RUN entsteht, ist ebenfalls abrufbar.
  • Du hast Deine HTML-Datei geändert, neu gebaut und in der Bau-Ausgabe gefunden, welche Schritte aus dem Cache kamen.
  • Du hast die Reflexionsfragen schriftlich beantwortet.

Arbeitsschritte

Ein Arbeitsverzeichnis mit einer eigenen Seite anlegen

mkdir meine-website

cd meine-website

echo "<h1>Meine Seite</h1>" > index.html

Hinweis: Alles, was in diesem Verzeichnis liegt, wird beim Bauen an den Docker-Dienst geschickt. Leg hier nichts ab, was nicht ins Image soll.

Das Dockerfile schreiben

Lege die Datei an:

nano Dockerfile

Schreib diese fünf Zeilen hinein:

FROM nginx:1.27.5
COPY index.html /usr/share/nginx/html/index.html
RUN echo "<h1>Beim Bauen entstanden</h1>" > /usr/share/nginx/html/gebaut.html
ENV MEIN_HINWEIS="Standardwert aus dem Image"
EXPOSE 80

Hinweis: Speichern in nano mit Strg+O und Enter, beenden mit Strg+X. Die Datei heißt genau Dockerfile – ohne Endung.

Überleg Dir, bevor Du weitermachst: Welche der fünf Zeilen läuft beim Bauen, welche beim Starten?

Ohne Namen bauen und nachsehen

docker image build .

docker images

Hinweis: Findest Du Dein Image in der Liste? Sieh in den Spalten REPOSITORY und TAG nach. Genau das ist der Grund, warum der nächste Schritt anders aussieht.

Mit Namen und Version bauen

docker image build -t meine-website:1.0.0 .

docker images

Einen Container starten und beide Seiten abrufen

docker container create --name website -p 8080:80 meine-website:1.0.0

docker container start website

curl http://localhost:8080

curl http://localhost:8080/gebaut.html

Prüfen, was EXPOSE bewirkt

Starte denselben Container ohne Port-Veröffentlichung:

docker container create --name website-ohne-port meine-website:1.0.0

docker container start website-ohne-port

curl http://localhost:8081

Hinweis: Im Dockerfile steht EXPOSE 80. Trotzdem kommst Du nicht heran. Was macht EXPOSE also – und was nicht?

docker container stop website-ohne-port

docker container rm website-ohne-port

Den Build-Cache beobachten

Bau noch einmal, ohne etwas zu ändern:

docker image build -t meine-website:1.0.0 .

Ändere jetzt Deine Seite und bau erneut:

echo "<h1>Meine Seite, zweite Fassung</h1>" > index.html

docker image build -t meine-website:1.0.1 .

Hinweis: Lies die Bau-Ausgabe Zeile für Zeile. Welche Schritte sind als CACHED markiert und welche nicht? Und jetzt die eigentliche Frage: Was wäre passiert, wenn die COPY-Zeile vor der FROM-Zeile stünde – und warum geht das gar nicht?

Zum Schluss aufräumen

docker container stop website

docker container rm website

Reflexionsfragen

  • Was passiert, wenn Du beim Bauen des Images den Parameter -t weglässt? Wie findest Du so ein Image später wieder?
  • Wofür wird EXPOSE im Dockerfile verwendet – und wofür nicht?
  • Wie setzt man Umgebungsvariablen im Image? Wenn Konfiguration doch von außen kommen soll: Wozu dann ENV?
  • Was ist der Unterschied zwischen ENTRYPOINT, CMD und RUN? Welche davon laufen beim Bauen, welche beim Starten?
  • Wofür kann man HEALTHCHECK verwenden? Warum reicht „der Prozess läuft“ nicht als Aussage?
  • Warum war der Build nach der Änderung an index.html schneller als der erste – und welche Schritte mussten trotzdem neu laufen?
