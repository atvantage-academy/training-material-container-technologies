Best Practices für Container Images

Kein Katalog zum Abhaken. Die fünfzehn Punkte sind nach dem gruppiert, was sie bewirken – such Dir die Gruppe, in der Dein Problem steckt.

Vier davon sind hervorgehoben: Wenn Du heute nur vier Dinge änderst, dann diese.

Größe Wie lange dauert Ziehen, Starten, Skalieren?

  • Multi-Stage-Build

    Compiler, Paketmanager und Testwerkzeuge gehören nicht in das, was läuft. Gebaut wird in der einen Stufe, kopiert wird in die andere.

    FROM golang:1.22 AS bau
RUN go build -o app

FROM alpine:3.19
COPY --from=bau /app /app
    größter Hebel
  • Schlankes Basis-Image

    Weniger Inhalt heißt weniger Ziehzeit, weniger Speicher und weniger, das eine Schwachstelle haben kann.

    FROM node:20-alpine
  • RUN-Befehle verketten

    Was in einem späteren Layer gelöscht wird, liegt weiter im früheren. Aufräumen muss im selben Layer geschehen.

    RUN apt-get update \
 && apt-get install -y curl \
 && rm -rf /var/lib/apt/lists/*
  • .dockerignore pflegen

    Der Punkt am Ende von docker build . schickt das ganze Verzeichnis an den Dienst – samt .git und node_modules.

    .git
node_modules
tests
*.log

Sicherheit Was kann jemand anfangen, der hineinkommt?

  • Nicht als root laufen

    Standard ist root – ohne Not. Manche Plattformen starten ein Image gar nicht erst, das nur als root läuft.

    RUN useradd -m anwendung
USER anwendung
    oft Startvoraussetzung
  • Nur nötige Ports nennen

    EXPOSE öffnet nichts, aber es dokumentiert. Eine Liste, die nicht stimmt, ist schlechter als keine.

    EXPOSE 8080
  • Regelmäßig scannen

    Ein Scan findet bekannte Schwachstellen in bekannten Paketen – nicht Fehler im eigenen Code und nicht, ob eine Lücke erreichbar ist.

    docker scout cves meinimage:1.0.0
trivy image meinimage:1.0.0
  • Keine Geheimnisse ins Image

    Was einmal in einem Layer steckt, bleibt dort – auch wenn eine spätere Zeile es löscht. Zugangsdaten kommen beim Start dazu.

    docker run -e DB_PASSWORT=... meinimage

Reproduzierbarkeit Kommt morgen dasselbe heraus?

  • Versionen pinnen

    Ohne Tag zieht der Build, was gerade aktuell ist. Derselbe Bauplan ergibt an zwei Tagen zwei Images – und der Unterschied fällt im Betrieb auf.

    FROM node:latest          # nicht so
FROM node:20.11-alpine    # besser
    Grundlage für alles Weitere
  • Auch ohne Änderung neu bauen

    Der Gegenpol zum Pinnen: Ein Image wird schlechter, ohne dass sich etwas ändert, weil seine Bestandteile altern. Ein turnusmäßiger Neubau zieht die Korrekturen mit.

    Pinnen und neu bauen – nicht das eine statt des anderen.

    wird am häufigsten vergessen
  • Layer-Reihenfolge nach Änderungshäufigkeit

    Stabiles zuerst, Wechselndes zuletzt. Sonst wird bei jeder Codeänderung alles neu installiert.

    COPY package*.json ./
RUN npm install
COPY . .
  • Ein Bauplan, viele Umgebungen

    Dasselbe Image läuft in Entwicklung, Test und Produktion. Was sich unterscheidet, kommt beim Start dazu – sonst ist das Artefakt in Produktion nicht das getestete.

    ENV APP_PORT=8080

Betrieb Kann die Plattform damit arbeiten?

  • Exec-Form für CMD und ENTRYPOINT

    In der Zeichenketten-Form schiebt sich eine Shell davor. Sie schluckt das Stopp-Signal – der Container wird dann nicht beendet, sondern abgeschossen.

    CMD node server.js          # nicht so
CMD ["node", "server.js"]   # besser
  • Ein Zweck je Container

    Webserver, Worker, Datenbank – getrennt. Zusammen lassen sie sich nicht getrennt aktualisieren, skalieren oder neu starten.

  • Logs nach stdout und stderr

    Wer in eine Datei schreibt, schreibt in einen Container, den es morgen nicht mehr gibt. Über den Ausgabestrom sammelt die Plattform mit.

    /var/log/app.log    # nicht so
stdout, stderr      # besser
  • Zustand nach draußen

    „Läuft“ heißt nicht „funktioniert“. Ein HEALTHCHECK sagt es selbst; persistente Daten gehören in ein Volume, nicht in den Container.

    HEALTHCHECK CMD curl -f \
  http://localhost:8080/health || exit 1

Merksatz: Die meisten dieser Punkte laufen auf dieselbe Frage hinaus – was gehört ins Image, und was kommt beim Start dazu? Wer sie beantworten kann, braucht die Liste nur noch zum Nachschlagen.
