    Einen Container aus einem fremden Image betreiben

    Als Entwicklerin möchte ich einen fertigen Webserver starten, ohne ihn zu installieren, damit ich sehe, was ein Image mitbringt – und was ich selbst dazugeben muss.

    Lernziele

    • Du ziehst Images aus einer Registry.
    • Du erkennst, welche Tags auf dasselbe Image zeigen und welche nicht.
    • Du erstellst, startest, stoppst und löschst Container.
    • Du erklärst den Lebenszyklus eines Containers und was Zustandslosigkeit bedeutet.

    Definition of Done

    • Ein Container mit nginx läuft und ist von außen erreichbar.
    • Ein zweiter Container liefert Deine eigene Seite aus.
    • Ein dritter Container liefert eine Seite aus, die auf Deinem Rechner liegt.
    • Du hast die Kontrollfragen beantwortet

    Arbeitsschritte

    Jeden Befehl kannst Du nachschlagen. Was er tut und welche Schalter er kennt, steht in der Docker CLI Reference – für den ersten Befehl dieser Übung etwa auf der Seite zu docker image pull.

    Ein Image ziehen

    Hol Dir zwei Stände desselben Images – einmal ohne Angabe eines Tags, einmal mit.

    docker image pull nginx

    docker image pull nginx:1.27.5

    Sieh Dir an, was jetzt lokal liegt:

    docker image ls

    Hinweis: Schau in der Spalte TAG genau hin. Welchen Tag hat der erste Befehl gezogen, obwohl Du keinen angegeben hast?

    Einen Container erzeugen und starten

    Erzeugen heißt noch nicht starten. Mach den Schritt bewusst einzeln.

    docker container create --name mein-webserver nginx:1.27.5

    Sieh nach, ob er da ist:

    docker container ls -a

    Jetzt starten – und den Webserver aus dem Container heraus fragen, denn darin lauscht er auf Port 80:

    docker container start mein-webserver

    docker container exec mein-webserver curl -s http://localhost

    Hinweis: Von innen antwortet er – der Webserver läuft also. Aus Deiner eigenen Shell erreichst Du ihn trotzdem nicht. Notiere, woran das liegen könnte, bevor Du weiterliest.

    Den Port nach außen geben

    Ob ein Port weitergegeben wird, entscheidet sich beim Erzeugen des Containers. Ein laufender Container lässt sich darin nicht mehr ändern – also weg damit und neu:

    docker container stop mein-webserver

    docker container rm mein-webserver

    docker container create --name mein-webserver -p 8080:80 nginx:1.27.5

    docker container start mein-webserver

    curl http://localhost:8080

    Hinweis: Arbeitest Du lokal, geht auch der Browser unter http://localhost:8080. In der bereitgestellten Umgebung läuft der Container nicht auf dem Rechner Deines Browsers – nimm dort curl aus derselben Shell.

    -p 8080:80 liest sich von außen nach innen: außen 8080, innen 80.

    Einen zweiten Container – mit einer eigenen Seite darin

    Stell einen zweiten Container daneben, ohne den ersten zu stoppen. Beide sollen gleichzeitig laufen und von außen erreichbar sein.

    Leg in diesem zweiten Container eine zusätzliche Seite an. Einen Befehl kannst Du auch innerhalb eines laufenden Containers ausführen lassen:

    docker container exec zweiter-webserver bash -c "echo 'Hallo Welt' > /usr/share/nginx/html/hallo.html"

    Teste, ob die neue Seite per HTTP erreichbar ist. Überprüfe, dass sie beim ersten Container nicht verfügbar ist.

    Stopp den zweiten Container und starte ihn wieder. Überprüfe, ob die Seite immer noch erreichbar ist.

    Ein dritter Container – die Seite liegt auf Deinem Rechner

    Bisher ist alles, was Du angelegt hast, im Container entstanden. Jetzt andersherum: Die Seite liegt bei Dir, der Container reicht sie nur durch.

    Leg auf Deinem Rechner ein Verzeichnis website an und darin eine Datei index.html mit etwas Inhalt.

    Erstelle einen dritten Container, diesmal mit einem zusätzlichen Parameter: Er hängt Dein Verzeichnis dorthin, wo NGINX seine Seiten sucht.

    -v "$(pwd)/website":/usr/share/nginx/html

    Git Bash unter Windows: Sie baut den Pfad im Container zu einem Windows-Pfad um – der Container findet das Verzeichnis dann nicht. Stell dem Aufruf in diesem Fall MSYS_NO_PATHCONV=1 voran:

    MSYS_NO_PATHCONV=1 docker container create ...

    Starte ihn und ruf die Seite auf. Ändere dann die Datei auf Deinem Rechner und ruf die Seite erneut auf – ohne den Container anzufassen.

    Hinweis: Das Verzeichnis einzuhängen heißt Bind Mount: Der Container sieht einen Ordner Deines Rechners an einer Stelle seines eigenen Dateisystems. Häng das Verzeichnis ein, nicht die einzelne Datei – viele Editoren legen beim Speichern eine neue Datei an, und die findet der Container dann nicht mehr.

    Zum Schluss aufräumen – erst, wenn Du alle drei nebeneinander gesehen hast:

    docker container stop mein-webserver zweiter-webserver dritter-webserver

    docker container rm mein-webserver zweiter-webserver dritter-webserver

    Reflexionsfragen

    • Der erste Container lief, war aber nicht erreichbar. Woran lag das?
    • Der zweite Container liefert hallo.html aus, der erste nicht – obwohl beide aus demselben Image stammen. Wie erklärst Du das? Was ist beim Stoppen und Neustarten mit der Datei passiert, und was würde passieren, wenn Du den Container löschst und neu erzeugst?
    • Für welche Anwendungsfälle sind Bind Mounts sinnvoll?
    • Was macht der folgende Befehl, und wozu wäre er nützlich? docker container run --rm -it nginx:1.27.5 /bin/sh
    • Welche Bedeutung hat das latest-Tag?
    • In der Dokumentation zu docker image pull steht ein Abschnitt Aliases. Wie ist er zu deuten?
