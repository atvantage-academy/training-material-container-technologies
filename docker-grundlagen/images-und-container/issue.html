Einen Container aus einem fremden Image betreiben

Als Entwicklerin möchte ich einen fertigen Webserver starten, ohne ihn zu installieren, damit ich sehe, was ein Image mitbringt – und was ich selbst dazugeben muss.

Lernziele

Du…

  • ziehst ein Image aus einer Registry und erkennst am Namen, welchen Stand Du bekommen hast.
  • erzeugst, startest, stoppst und löschst einen Container mit jeweils einem eigenen Befehl.
  • listest laufende und angehaltene Container auf und unterscheidest die beiden Zustände.
  • führst einen Befehl in einem laufenden Container aus.
  • sagst voraus, was mit einer Datei im Container passiert, wenn er gestoppt bzw. gelöscht wird – und prüfst Deine Vorhersage.

Definition of Done

  • Du hast nginx in zwei verschiedenen Ständen gezogen und beide in der Image-Liste gefunden.
  • Ein Container mit dem Namen mein-webserver läuft und liefert im Browser bzw. über curl die NGINX-Startseite aus.
  • Du hast im laufenden Container eine zusätzliche Seite angelegt und sie abgerufen.
  • Du hast den Container gestoppt, wieder gestartet und geprüft, ob die Seite noch da ist.
  • Du hast den Container gelöscht, einen neuen aus demselben Image erzeugt und geprüft, ob die Seite noch da ist.
  • Du hast die Reflexionsfragen schriftlich beantwortet.

Arbeitsschritte

Ein Image ziehen

Hol Dir zwei Stände desselben Images – einmal ohne Angabe eines Tags, einmal mit.

docker pull nginx

docker pull nginx:1.27.5

Sieh Dir an, was jetzt lokal liegt:

docker images

Hinweis: Schau in der Spalte TAG genau hin. Welchen Tag hat der erste Befehl gezogen, obwohl Du keinen angegeben hast?

Dem Image ein eigenes Etikett geben

Ein Image kann mehrere Namen tragen, ohne dass es zweimal auf der Platte liegt.

docker image tag nginx:1.27.5 mein-http:1.0.0

docker images

Hinweis: Vergleiche die Spalte IMAGE ID der beiden Zeilen. Was sagt Dir das darüber, was ein Tag eigentlich ist?

Einen Container erzeugen

Erzeugen heißt noch nicht starten. Mach den Schritt bewusst einzeln.

docker container create --name mein-webserver -p 8080:80 mein-http:1.0.0

Sieh nach, ob er da ist:

docker container ls

docker container ls -a

Hinweis: Der erste Befehl zeigt Dir nichts, der zweite schon. Das ist kein Fehler – merk Dir den Unterschied, Du wirst ihn noch oft brauchen.

Den Container starten und aufrufen

docker container start mein-webserver

Ruf den Webserver auf:

curl http://localhost:8080

Hinweis: Arbeitest Du lokal, geht auch der Browser unter http://localhost:8080. In der bereitgestellten Umgebung läuft der Container nicht auf dem Rechner Deines Browsers – nimm dort curl aus derselben Shell.

Eine Datei im Container anlegen

Du kannst einen Befehl innerhalb eines laufenden Containers ausführen lassen.

docker container exec mein-webserver bash -c "echo 'Hallo Welt' > /usr/share/nginx/html/hallo.html"

Prüfe, ob die neue Seite ausgeliefert wird:

curl http://localhost:8080/hallo.html

Stoppen, neu starten und nachsehen

docker container stop mein-webserver

docker container start mein-webserver

curl http://localhost:8080/hallo.html

Hinweis: Notiere Dein Ergebnis, bevor Du weitermachst. Gleich wird es interessant.

Löschen, neu erzeugen und nachsehen

Überleg Dir vorher, was Du erwartest – dann probiere es aus.

docker container stop mein-webserver

docker container rm mein-webserver

docker container create --name mein-webserver -p 8080:80 mein-http:1.0.0

docker container start mein-webserver

curl http://localhost:8080/hallo.html

Hinweis: Wenn das Ergebnis Dich überrascht, hast Du gerade den wichtigsten Punkt dieser Übung gefunden. Schreib ihn auf.

Zum Schluss aufräumen

docker container stop mein-webserver

docker container rm mein-webserver

Reflexionsfragen

  • Was sind Tags und wofür werden sie verwendet?
  • Was passiert, wenn Du beim Erzeugen des Containers keinen Namen angibst?
  • Was bedeuten beim Erzeugen eines Containers die Parameter -e, -v und -p? Was haben sie gemeinsam?
  • Was ist mit der Datei hallo.html passiert, als der Container gestoppt wurde? Und als er gelöscht und neu angelegt wurde? Wie erklärst Du den Unterschied?
  • Was macht der folgende Befehl, und wozu wäre er nützlich? docker run --rm -it nginx:1.27.5 /bin/sh
