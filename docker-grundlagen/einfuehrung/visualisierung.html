Merksatz: Das Image ist der Bauplan und liegt in der Registry, der Container ist die laufende Ausprägung auf Deinem Rechner – und dazwischen steht immer der Docker Daemon.

Alle Erläuterungen

Registry: Organisation, Repository, Tag

Der Ort, an dem Images liegen. Docker Hub ist eine davon; viele Häuser betreiben eine eigene (Harbor, Nexus, GitHub Container Registry).

Der vollständige Name sagt, wo ein Image liegt und welche Fassung gemeint ist:

registry.example.com/mein-team/webshop:1.4

TeilWas er benennt
registry.example.comDie Registry. Fehlt sie, ist Docker Hub gemeint.
mein-teamDie Organisation: wem der Name gehört.
webshopDas Repository: alle Fassungen einer Software.
1.4Der Tag: die Fassung. Fehlt er, gilt latest.

Ein Tag ist ein Zeiger, kein Stand. Er lässt sich umhängen; eindeutig ist nur der Digest. Für private Repositories und jedes Veröffentlichen: docker login.

Das Image

Der unveränderliche Bauplan: ein fertiges Dateisystem und die Angaben, wie daraus ein Container wird.

Hash

Jedes Image trägt einen sha256:…-Digest, gerechnet aus seinem Inhalt.

  • Gleicher Inhalt → gleicher Digest, in jeder Registry.
  • Ändert sich der Inhalt, ändert sich der Digest – es ist dann ein anderes Image.
  • Mehrere Tags dürfen auf denselben Digest zeigen.

Anzeigen: docker image ls --digests

Metadaten

Im Image steckt mehr als das Dateisystem – und all das reist mit:

  • Erstellungszeitpunkt und Autor
  • Architektur und Betriebssystem (linux/amd64)
  • Startbefehl und Arbeitsverzeichnis
  • Ports und vorbelegte Umgebungsvariablen
  • Labels: Titel, Beschreibung, Version, Quelle, Lizenz

Ansehen: docker image inspect mein-team/webshop:1.4

Docker Daemon: der, der arbeitet

Ein Dienst auf dem Rechner. Er spricht mit der Registry, lädt Images, legt Container an, startet und stoppt sie und verwaltet Speicher, Netze und Volumes.

Alles, was Du tippst, führt er aus – nicht die CLI. Die schickt nur einen Auftrag über die Docker-API.

  • Pfade gelten dort, wo der Daemon läuft – bei einem entfernten Daemon ist das ein anderer Rechner.
  • Läuft er nicht, geht nichts: „Cannot connect to the Docker daemon“.
  • Wer mit ihm sprechen darf, darf viel – eine Rechtefrage auf dem Rechner.

Docker CLI: die Befehle

Dein Befehlswerkzeug. Sie tut selbst nichts – sie beauftragt den Daemon.

BefehlWofür
docker loginan einer Registry anmelden
docker image pull <name>:<tag>Image holen
docker image push <name>:<tag>Image veröffentlichen
docker image lslokale Images auflisten
docker container create <image>Container anlegen
docker container start <name>Container starten
docker container stop <name>Container anhalten
docker container ls --allContainer auflisten, auch gestoppte
docker container logs <name>Ausgaben ansehen
docker container rm <name>Container entfernen
docker container run <image>anlegen und starten in einem

Immer die Langform – docker image pull statt docker pull. Sie sagt, worauf der Befehl wirkt; genau diese Unterscheidung übt der Kurs. Alle Befehle mit allen Schaltern: Docker-CLI-Referenz

Images auf Deinem Rechner

Hier liegt dasselbe Image wie in der Registry – inhaltlich identisch, mit demselben Digest. Kein zweites Original, sondern eine gecachte Kopie im Speicher des Daemons.

  • docker image pull legt die Kopie an; ein zweiter Aufruf lädt nur, was noch fehlt.
  • docker image rm löscht die Kopie – in der Registry bleibt das Image.
  • docker image tag hängt einen zweiten Namen an denselben Digest. Das brauchst Du vor dem docker image push: Der Name muss zur Ziel-Registry passen.

Container: der Lebenszyklus

Die laufende Ausprägung eines Images: eigene Prozesse, eigene Umgebungsvariablen, ein eigener beschreibbarer Bereich. Aus einem Image können viele Container werden.

docker container run legt an und startet in einem Schritt.

Docker unterscheidet im nicht laufenden Zustand zwei Fälle: created (noch nie gelaufen) und exited (schon gelaufen, mit Rückgabewert und Protokoll). Für das Bedienen macht das keinen Unterschied – docker container start führt aus beiden ins Laufen.

Beim Entfernen ist alles weg, was im Container entstanden ist – was dagegen hilft, ist Thema des Blocks über Konfiguration und Zustand.
