Die ganze Landschaft mit einem Befehl starten

Als Mitglied des Teams möchte ich unsere Umgebung in einer Datei beschreiben, damit eine neue Kollegin sie mit einem Befehl aufbauen kann – ohne dass ihr jemand fünfzehn docker-Aufrufe diktiert.

Lernziele

Du…

  • überführst eine Folge von docker-Befehlen in eine Compose-Beschreibung und ordnest jeden Parameter dem passenden Schlüssel zu.
  • startest, stoppst und entfernst eine mehrteilige Umgebung mit je einem Befehl.
  • sprichst einen Service von einem anderen aus über seinen Servicenamen an, ohne ein Netzwerk angelegt zu haben.
  • unterscheidest down von down -v und benennst, was jeweils verloren geht.
  • erklärst, was depends_on garantiert und was nicht.

Definition of Done

  • Eine Datei compose.yaml beschreibt drei Services: datenbank, website und werkzeug.
  • docker compose up -d startet alle drei, docker compose ps zeigt sie.
  • Deine Seite ist unter Port 8080 abrufbar.
  • Aus dem Service werkzeug heraus erreichst Du die Datenbank über den Namen datenbank – ohne dass Du ein Netzwerk angelegt hast.
  • Nach docker compose down und erneutem up -d sind Deine Tabellendaten noch da.
  • Du hast die Reflexionsfragen schriftlich beantwortet.

Arbeitsschritte

Aufräumen und ein Projektverzeichnis anlegen

Die Container von heute Vormittag belegen Namen und Ports.

docker container stop meine-db

docker container rm meine-db

mkdir ~/meine-landschaft

cd ~/meine-landschaft

mkdir html

echo "<h1>Meine Landschaft</h1>" > html/index.html

Die Beschreibung schreiben

nano compose.yaml

Schreib diese Beschreibung hinein:

services:

  datenbank:
    image: postgres:18
    environment:
      POSTGRES_DB: helloworld
      POSTGRES_USER: kurs
      POSTGRES_PASSWORD: geheim
    volumes:
      - db-daten:/var/lib/postgresql/data

  website:
    image: nginx:1.27.5
    ports:
      - "8080:80"
    volumes:
      - ./html:/usr/share/nginx/html:ro

  werkzeug:
    image: postgres:18
    command: ["sleep", "infinity"]
    environment:
      PGPASSWORD: geheim
    depends_on:
      - datenbank

volumes:
  db-daten:

Hinweis: YAML kennt keine Tabulatoren, nur Leerzeichen. Wenn Dein Editor beim Tippen Tabulatoren einfügt, bricht die Datei – und die Meldung nennt nur die Zeilennummer, nicht die Ursache.

Bevor Du startest: Geh die Datei mit Deiner Partnerin durch und ordne jeder Zeile den docker-Parameter von heute Vormittag zu, der ihr entspricht.

Die Landschaft starten

docker compose up -d

docker compose ps

curl http://localhost:8080

Nachsehen, was Compose angelegt hat

docker network ls

docker volume ls

Hinweis: Du hast weder ein Netzwerk noch ein Volume von Hand angelegt. Trotzdem sind beide da. Merk Dir die Namen – woraus sind sie gebildet?

Die Datenbank über ihren Servicenamen erreichen

docker compose exec werkzeug psql -h datenbank -U kurs -d helloworld -c "SELECT 1"

Hinweis: Beachte, was hier nicht steht: kein docker network create, keine IP-Adresse, kein veröffentlichter Port an der Datenbank. Woher kennt werkzeug die Adresse von datenbank?

Daten anlegen

docker compose exec werkzeug psql -h datenbank -U kurs -d helloworld -c "CREATE TABLE gruss (id SERIAL PRIMARY KEY, text TEXT NOT NULL)"

docker compose exec werkzeug psql -h datenbank -U kurs -d helloworld -c "INSERT INTO gruss (text) VALUES ('Hallo aus Compose')"

docker compose exec werkzeug psql -h datenbank -U kurs -d helloworld -c "SELECT * FROM gruss"

Alles wegräumen und wieder aufbauen

docker compose down

docker compose ps -a

docker compose up -d

docker compose exec werkzeug psql -h datenbank -U kurs -d helloworld -c "SELECT * FROM gruss"

Hinweis: Die Container waren weg und sind neu. Die Daten sind da. Erklär Dir selbst, warum – Du hast die Antwort heute Vormittag erarbeitet.

In die Log-Ausgaben sehen

docker compose logs datenbank

Hinweis: Such in der Ausgabe die Zeile, ab der die Datenbank Verbindungen annimmt. Wie lange hat es vom Start bis dahin gedauert? Was hieße das für einen Service, der sich sofort verbinden will?

Bonus (freiwillig): eine Anwendung dazwischensetzen

Nur, wenn Du früh fertig bist. Leg eine kleine Anwendung an, die aus der Datenbank liest:

mkdir app

nano app/server.py

import os
from flask import Flask, jsonify
import psycopg2

app = Flask(__name__)

@app.route("/gruesse")
def gruesse():
    verbindung = psycopg2.connect(
        host=os.getenv("DB_HOST", "datenbank"),
        dbname=os.getenv("DB_NAME", "helloworld"),
        user=os.getenv("DB_USER", "kurs"),
        password=os.getenv("DB_PASSWORD", "geheim"),
    )
    zeiger = verbindung.cursor()
    zeiger.execute("SELECT text FROM gruss")
    ergebnis = [zeile[0] for zeile in zeiger.fetchall()]
    verbindung.close()
    return jsonify(ergebnis)

app.run(host="0.0.0.0", port=5000)

Ergänze in compose.yaml einen vierten Service (auf derselben Ebene wie die anderen):

  anwendung:
    image: python:3.12-slim
    working_dir: /app
    command: sh -c "pip install --no-cache-dir flask psycopg2-binary && python server.py"
    environment:
      DB_HOST: datenbank
    ports:
      - "8081:5000"
    volumes:
      - ./app:/app
    depends_on:
      - datenbank

docker compose up -d

curl http://localhost:8081/gruesse

Hinweis: Beim allerersten Start kann der Aufruf scheitern – die Anwendung installiert erst ihre Abhängigkeiten. Sieh mit docker compose logs anwendung nach, was gerade passiert.

Reflexionsfragen

  • Welches Netzwerk hast Du angelegt, damit die Services einander finden?
  • Wodurch unterscheidet sich der Servicename vom Container-Namen? Welcher von beiden ist die Adresse?
  • Was garantiert depends_on – und was garantiert es ausdrücklich nicht? Welchen Fehler erzeugt diese Verwechslung, und wann fällt er auf?
  • Was ist der Unterschied zwischen docker compose down und docker compose down -v?
  • Was hat sich gegenüber den Einzelbefehlen von heute Vormittag inhaltlich geändert – und was nicht?
  • Würdest Du eine solche Datei für den Produktionsbetrieb verwenden? Woran würdest Du merken, dass sie nicht mehr reicht?
