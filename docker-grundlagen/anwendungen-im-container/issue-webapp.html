Eine Webanwendung mit Abhängigkeiten betreiben

Als Entwicklerin möchte ich eine kleine Webanwendung im Container starten, damit ich sehe, was passiert, wenn die Anwendung etwas braucht, das im Image nicht drin ist.

Lernziele

Du…

  • betreibst eine Anwendung, deren Abhängigkeiten im gewählten Image fehlen.
  • machst einen Dienst aus dem Container heraus erreichbar.
  • erkennst, warum eine Anwendung im Container auf allen Adressen lauschen muss.
  • benennst, was Du weitergeben müsstest, damit jemand anders dasselbe Ergebnis bekommt.

Definition of Done

  • Die Anwendung antwortet auf curl http://localhost:8080 mit ihrer Seite.
  • Du hast die Abhängigkeit nicht auf Deinem Rechner installiert.
  • Deine befehle.md enthält jeden Befehl, der nötig war – in der richtigen Reihenfolge.
  • Du hast die Reflexionsfragen schriftlich beantwortet.

Dein Auftrag

Auch hier: keine Befehlsfolge. Du hast alles, was Du brauchst.

Leg zwei Dateien an.

app.py:

from flask import Flask

app = Flask(__name__)

@app.get("/")
def start():
    return "Hallo aus der Webanwendung!\n"

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=8080)

requirements.txt:

flask==3.0.3

Bring die Anwendung in einem Container zum Laufen, sodass sie von außen unter Port 8080 antwortet.

Hinweis: Das Python-Image bringt Flask nicht mit. Die Abhängigkeiten stehen in requirements.txt; installieren lassen sie sich mit pip install -r requirements.txt. Überleg Dir, wann dieser Befehl laufen muss – und wo.

Hinweis: Wenn in Deiner Umgebung kein Paket aus dem Netz geladen werden darf, nennt Dir der Trainer ein Image, in dem Flask schon enthalten ist. Dann entfällt der Installationsschritt.

Hinweis für die Git Bash unter Windows: Hängst Du ein Verzeichnis ein, baut die Git Bash den Pfad im Container zu einem Windows-Pfad um – der Container findet die Datei dann nicht. Stell dem Aufruf in diesem Fall MSYS_NO_PATHCONV=1 voran: MSYS_NO_PATHCONV=1 docker run ...

Achtung, häufigste Falle: Eine Webanwendung, die nur auf 127.0.0.1 lauscht, ist von außerhalb des Containers nicht erreichbar – auch dann nicht, wenn der Port weitergegeben ist. Im Code oben steht deshalb host="0.0.0.0". Wenn nichts antwortet, sieh Dir zuerst die Ausgabe des Containers an.

Reflexionsfragen

  • Wie oft wurde Flask installiert, bis Deine Anwendung lief? Wie lange hat das jedes Mal gedauert?
  • Was passiert mit der Installation, wenn der Container gelöscht wird?
  • Was müsstest Du weitergeben, damit eine Kollegin dieselbe Anwendung starten kann? Schreib die vollständige Liste auf – Du brauchst sie im nächsten Block wieder.
  • Warum genügt es nicht, den Port nach außen zu legen, wenn die Anwendung nur auf 127.0.0.1 lauscht?
