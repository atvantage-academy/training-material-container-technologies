Ein Python-Skript im Container ausführen

Als Entwickler möchte ich ein Skript ausführen, ohne Python zu installieren, damit es auf jedem Rechner gleich läuft.

Lernziele

Du…

  • suchst Dir selbst ein Image, das eine bestimmte Laufzeitumgebung mitbringt.
  • bringst eine Datei von Deinem Rechner in einen Container.
  • führst eine Anwendung in einem Container aus, ohne einen Container zurückzulassen.
  • erklärst, wo Dein Skript liegt – im Image oder daneben.

Definition of Done

  • Das Skript läuft in einem Container und gibt seine Zeile aus.
  • Auf Deinem Rechner ist kein Python installiert worden.
  • Nach dem Lauf ist kein Container übrig (docker container ls -a).
  • Der Befehl, der funktioniert hat, steht in Deiner befehle.md.
  • Du hast die Reflexionsfragen schriftlich beantwortet.

Dein Auftrag

Diese Übung nennt kein einziges Kommando. Das ist Absicht: Du hast alles gesehen, was Du brauchst – den Rest findest Du in der Referenz oder bei Deiner Partnerin.

Leg eine Datei hello.py an, mit dem Editor Deiner Wahl:

print("Hallo aus dem Container!")

Bring sie in einem Container zur Ausführung. Es gibt mehr als einen Weg.

Hinweis: Eine Datei kann auf zwei Arten in einen Container gelangen: Du hängst das Verzeichnis beim Start ein, oder Du kopierst sie in einen laufenden Container hinein. Beides ist hier erlaubt.

Hinweis: Ab dieser Übung gilt die Empfehlung docker run --rm. Sonst sammeln sich beim Ausprobieren Container an, die niemand mehr braucht.

Hinweis für die Git Bash unter Windows: Hängst Du ein Verzeichnis ein, baut die Git Bash den Pfad im Container zu einem Windows-Pfad um – der Container findet die Datei dann nicht. Stell dem Aufruf in diesem Fall MSYS_NO_PATHCONV=1 voran: MSYS_NO_PATHCONV=1 docker run ...

Reflexionsfragen

  • Welches Image hast Du genommen, und warum gerade dieses? Was hättest Du stattdessen nehmen können?
  • Lag Dein Skript im Image oder daneben? Woran erkennst Du das?
  • Was müsstest Du einer Kollegin schicken, damit sie genau dasselbe Ergebnis bekommt?
  • Was ist nach dem Lauf mit dem Container passiert – und was wäre ohne --rm passiert?
