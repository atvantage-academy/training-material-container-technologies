Die Webanwendung spricht mit der Datenbank

Als Entwicklerin möchte ich, dass meine Anwendung ihre Datenbank findet, ohne eine IP-Adresse zu kennen, damit dieselbe Anwendung in jeder Umgebung läuft.

Lernziele

Du…

  • legst ein eigenes Netzwerk an und hängst Container hinein.
  • sprichst einen Container über seinen Namen an statt über eine IP-Adresse.
  • gibst einer Anwendung die Adresse ihrer Datenbank von außen mit.
  • erklärst, warum localhost hier die falsche Adresse ist.

Definition of Done

  • Ein Netzwerk helloworld-network existiert, und beide Container hängen darin.
  • curl http://localhost:8080 liefert den Text, der in der Datenbanktabelle gruss steht.
  • Du hast die Reflexionsfragen schriftlich beantwortet.

Arbeitsschritte

Ein Netzwerk anlegen

Das ist neu – deshalb steht es hier vollständig:

docker network create helloworld-network

docker network ls

Die Datenbank in das Netzwerk hängen

Ein laufender Container wechselt das Netzwerk nicht nachträglich. Erzeuge die Datenbank aus der vorigen Übung neu – mit denselben Umgebungsvariablen, demselben Volume und zusätzlich:

--network helloworld-network

Hinweis: Das Volume kurs-daten sorgt dafür, dass Deine Tabelle gruss noch da ist – prüf das, bevor Du weitermachst.

Die Anwendung liest aus der Datenbank

Das hier ist eine neue Anwendung: Sie holt ihre Begrüßungen aus der Datenbank. Ob Du app.py damit ersetzt oder sie als zweite Datei danebenlegst, bleibt Dir überlassen.

import os
from flask import Flask
import psycopg2

app = Flask(__name__)

# Konfiguration aus der Umgebung – die Werte dahinter gelten nur,
# solange nichts gesetzt ist.
DB_NAME = os.getenv("DB_NAME", "helloworld")
DB_USER = os.getenv("DB_USER", "postgres")
DB_HOST = os.getenv("DB_HOST", "localhost")
DB_PORT = os.getenv("DB_PORT", "5432")

# Das Passwort darf auch aus einer Datei kommen: DB_PASSWORD_FILE nennt den Pfad.
PASSWORD_FILE = os.getenv("DB_PASSWORD_FILE")
if PASSWORD_FILE:
    with open(PASSWORD_FILE) as datei:
        DB_PASSWORD = datei.read().strip()
else:
    DB_PASSWORD = os.getenv("DB_PASSWORD", "postgres")

@app.get("/")
def start():
    connection = psycopg2.connect(
        dbname=DB_NAME,
        user=DB_USER,
        password=DB_PASSWORD,
        host=DB_HOST,
        port=DB_PORT,
    )
    cursor = connection.cursor()
    cursor.execute("SELECT text FROM gruss")
    rows = cursor.fetchall()
    cursor.close()
    connection.close()
    return "\n".join(row[0] for row in rows) + "\n"

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=8080)

Verwende diese requirements.txt:

flask==3.0.3
psycopg2-binary==2.9.13

Die Anwendung starten

Starte sie wie in der vorigen Übung – mit drei Ergänzungen:

  • Sie gehört in dasselbe Netzwerk: --network helloworld-network

  • Sie bekommt die Angaben zur Datenbank mit – dieselben, mit denen Du sie eingerichtet hast:

    -e DB_HOST=meine-db -e DB_NAME=helloworld -e DB_USER=kurs -e DB_PASSWORD=geheim
  • Der Port 8080 muss nach außen.

Hinweis: Benutzer und Passwort sind sehr wohl nötig: Die Werte im Quelltext sind nur Vorgaben, und postgres/postgres kennt Deine Datenbank nicht. Allein DB_PORT kannst Du weglassen – 5432 stimmt bereits.

Sieh Dir DB_HOST genau an. meine-db ist der Name des Datenbank-Containers – nicht localhost, nicht eine IP.

Ruf die Anwendung auf:

curl http://localhost:8080

Hinweis: Wenn eine Fehlermeldung kommt, lies sie zu Ende. „Connection refused“ heißt etwas anderes als „could not translate host name“ – das eine ist ein Zeitproblem, das andere ein Namensproblem.

Optional: Das Passwort aus einer Datei lesen

In der Datenbank-Übung hast Du das Passwort aus einer Datei gelesen statt aus einer Variablen. Die Anwendung kann das auch: Ist DB_PASSWORD_FILE gesetzt, nimmt sie den Inhalt der genannten Datei.

Leg die Datei an und reich sie hinein – statt -e DB_PASSWORD=geheim:

echo 'geheim' > db-passwort.txt

-v "$(pwd)/db-passwort.txt":/run/secrets/db-passwort
-e DB_PASSWORD_FILE=/run/secrets/db-passwort

Hinweis: Dieselbe Datei kann auch die Datenbank lesen – dort heißt die Variable POSTGRES_PASSWORD_FILE. Dann steht das Passwort an genau einer Stelle, und die liegt nicht in der Prozessliste.

Den Namen auf die Probe stellen

Stopp den Datenbank-Container, ruf die Anwendung erneut auf und sieh Dir an, was passiert. Starte die Datenbank danach wieder.

Reflexionsfragen

  • Warum funktioniert meine-db als Adresse, und warum wäre localhost falsch?
  • Welche Angaben gibst Du der Anwendung von außen mit? Warum stehen im Quelltext nur Vorgabewerte und nicht Deine eigenen?
  • Was ist passiert, als die Datenbank weg war? Wie sollte sich eine Anwendung in diesem Fall verhalten?
