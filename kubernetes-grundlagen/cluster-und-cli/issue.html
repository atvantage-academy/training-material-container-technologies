    Erste Schritte mit kubectl

    User Story

    Als Entwickler:in möchte ich mich am Cluster anmelden und mich darin zurechtfinden, damit ich weiß, wo meine Anwendung gleich laufen wird und welche Ressourcen mir dafür zur Verfügung stehen.

    Lernziele
    • Du prüfst, mit welchem Cluster und welchem Namespace kubectl gerade spricht.
    • Du listest Nodes und Pods auf und deutest eine Fehlermeldung zu fehlenden Rechten.
    • Du arbeitest in Deinem eigenen Namespace.
    • Du findest mit kubectl api-resources und kubectl explain selbst heraus, welche Ressourcen es gibt und welche Felder sie haben.
    Definition of Done
    • kubectl config get-contexts zeigt Deinen Kontext mit Deinem Namespace in der Spalte NAMESPACE.
    • kubectl get pods antwortet in Deinem Namespace – mit „No resources found“, solange dort noch nichts läuft.
    • Du kannst mit kubectl explain erklären, was das Feld spec.replicas eines Deployments bedeutet.
    • Du hast die Kontrollfragen beantwortet

    Arbeitsschritte

    Hinweis: Ob Du im bereitgestellten Cluster oder lokal auf Minikube arbeitest, steht in der Schulungsumgebung. Die Befehle sind in beiden Fällen dieselben; wo das Ergebnis abweicht, steht es dabei.

    Den Kontext prüfen

    kubectl muss wissen, mit welchem Cluster es spricht. Melde Dich zuerst so am Cluster an, wie es die Schulungsumgebung beschreibt – auf Minikube ist das schon geschehen.

    # Welche Version hat kubectl, welche der Cluster?
kubectl version

    # Mit welchem Kontext arbeitest Du gerade?
kubectl config current-context

    # Alle Kontexte – der gewählte ist mit * markiert, rechts steht der Namespace
kubectl config get-contexts

    Die Nodes ansehen

    kubectl get nodes

    Auf Minikube siehst Du genau einen Node – Control Plane und Worker auf einer Maschine.

    Hinweis: Im bereitgestellten Cluster kann dieser Befehl mit Forbidden scheitern. Das ist kein Fehler Deiner Eingabe: Nodes gehören dem ganzen Cluster, und Deine Rechte reichen nur bis zu Deinem Namespace. Lies die Fehlermeldung zu Ende – sie nennt die Ressource und den Benutzer.

    Alle Pods des Clusters ansehen

    # -A steht für --all-namespaces
kubectl get pods -A

    Such in der Ausgabe nach dem Namespace kube-system. Erkennst Du die Bausteine aus dem Tafelbild wieder?

    Hinweis: Auch dieser Befehl kann im bereitgestellten Cluster an den Rechten scheitern. Dann siehst Du nur Deinen eigenen Namespace – weiter mit dem nächsten Schritt.

    In Deinem eigenen Namespace arbeiten

    Jede Ressource, die Du im Kurs anlegst, landet in einem Namespace. Welcher das ist, steht im Kontext.

    Im bereitgestellten Cluster hast Du bereits einen eigenen Namespace; Du darfst keinen neuen anlegen. Prüf mit kubectl config get-contexts, dass er in der Spalte NAMESPACE steht. Steht dort nichts, setzt Du ihn so:

    kubectl config set-context --current --namespace=<dein-namespace>

    Auf Minikube legst Du Dir einen an und machst ihn zum Standard:

    kubectl create namespace recipes

    kubectl config set-context --current --namespace=recipes

    Prüf das Ergebnis:

    kubectl get pods

    „No resources found in … namespace.“ ist hier die richtige Antwort – der Name in der Meldung ist Dein Namespace.

    Herausfinden, welche Ressourcen es gibt

    kubectl api-resources

    Such in der Liste nach deployments, services, ingresses und configmaps. Die Spalte SHORTNAMES nennt Kurzformen; im Kurs schreiben wir die Namen aus. Die Spalte NAMESPACED zeigt, ob eine Ressource zu einem Namespace gehört – sieh nach, was dort bei nodes steht.

    Die Felder einer Ressource nachschlagen

    kubectl explain deployment

    Mit Punkten gehst Du tiefer:

    kubectl explain deployment.spec.replicas

    kubectl explain deployment.spec.template.spec.containers

    Diese Beschreibung brauchst Du in den nächsten Übungen, wenn ein Feld unklar ist.

    Reflexionsfragen

    • Mit wem spricht kubectl eigentlich, wenn Du kubectl get pods eingibst?
    • Warum durftest Du (vielleicht) die Nodes nicht sehen, Deine eigenen Pods aber schon?
    • Wie findest Du heraus, welche Felder ein Deployment hat, ohne im Internet zu suchen?
