    Das Backend deployen

    User Story

    Als Entwickler:in möchte ich das Backend der Rezeptverwaltung als Container in Kubernetes deployen, damit es über eine öffentliche URL erreichbar ist.

    Lernziele
    • Du erstellst ein Deployment mit einem YAML-Manifest und wendest es auf den Cluster an.
    • Du prüfst den Status eines Pods.
    • Du machst eine Anwendung mit einem Service im Cluster und mit einem Ingress von außen erreichbar.
    Definition of Done
    • kubectl get pods zeigt den Pod recipes-backend-… im Status Running.
    • kubectl get service,ingress zeigt einen Service und einen Ingress namens recipes-backend.
    • curl -i http://<backend-host>/recipes antwortet mit HTTP/1.1 200 OK und einer JSON-Liste.
    • Du hast die Kontrollfragen beantwortet

    Arbeitsschritte

    Das Deployment erstellen

    Erstelle eine Datei backend-deployment.yaml mit folgendem Inhalt:

    apiVersion: apps/v1
kind: Deployment
metadata:
  name: recipes-backend
spec:
  replicas: 1
  selector:
    matchLabels:
      app: recipes-backend
  template:
    metadata:
      labels:
        app: recipes-backend
    spec:
      containers:
        - name: recipes-backend
          image: ralfueberfuhr/recipes-backend:latest-dev
          ports:
            - containerPort: 8080

    Hinweis: Das Tag latest-dev enthält eine eingebaute H2-Datenbank im Speicher und braucht keine externe Datenbank – ideal für den ersten Schritt.

    Wende das Manifest an:

    kubectl apply -f backend-deployment.yaml

    Den Status des Pods prüfen

    kubectl get pods

    Nach kurzer Zeit sollte der Pod im Status Running sein.

    Hinweis: Bleibt der Pod bei ErrImagePull oder ImagePullBackOff stehen, liegt das meist am Rate Limiting von Docker Hub für anonyme Zugriffe. Leg dann ein Pull Secret mit Deinem Docker-Hub-Konto an:

    kubectl create secret docker-registry dockerhub-pull-secret \
  --docker-server=docker.io \
  --docker-username=<dein-dockerhub-benutzer> \
  --docker-password=<dein-dockerhub-token>

    und ergänze es im Deployment:

        spec:
      imagePullSecrets:
        - name: dockerhub-pull-secret
      containers:
        - name: recipes-backend

    Danach erneut kubectl apply -f backend-deployment.yaml.

    Einen Service erstellen

    Erstelle eine Datei backend-service.yaml:

    apiVersion: v1
kind: Service
metadata:
  name: recipes-backend
spec:
  selector:
    app: recipes-backend
  ports:
    - port: 8080
      targetPort: 8080

    kubectl apply -f backend-service.yaml

    Einen Ingress erstellen

    Der Ingress braucht einen Hostnamen, unter dem das Backend von außen erreichbar ist. Welcher das ist, hängt von Deiner Umgebung ab:

    • Minikube: recipes-backend.127.0.0.1.nip.io. nip.io ist ein DNS-Dienst, der einen Hostnamen auf die darin enthaltene IP-Adresse auflöst – hier also auf 127.0.0.1.
    • Bereitgestellter Cluster: ein Hostname nach dem Schema, das die Schulungsumgebung nennt. Er muss im Cluster eindeutig sein.

    Diesen Hostnamen nennen die folgenden Übungen <backend-host>. Erstelle eine Datei backend-ingress.yaml und setze ihn ein:

    apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: recipes-backend
spec:
  rules:
    - host: <backend-host>
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: recipes-backend
                port:
                  number: 8080

    kubectl apply -f backend-ingress.yaml

    kubectl get ingress recipes-backend

    Hinweis: Ein Ingress wirkt nur, wenn im Cluster ein Ingress Controller läuft. Im bereitgestellten Cluster ist das so; auf Minikube aktiviert ihn das Addon ingress (siehe Minikube für die Schulung einrichten).

    Den Ingress testen

    Nur auf Minikube: Damit der Ingress von Deinem Rechner aus erreichbar ist, muss in einem eigenen Terminal dieser Befehl laufen – lass es offen:

    minikube tunnel

    Ruf dann die API auf:

    curl -i http://<backend-host>/recipes

    Dieselbe Adresse kannst Du auch im Browser öffnen.
