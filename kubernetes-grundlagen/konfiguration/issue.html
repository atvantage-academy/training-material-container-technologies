    Konfiguration in ConfigMaps auslagern

    User Story

    Als Entwickler:in möchte ich die Adresse des Backends in einer ConfigMap verwalten, damit ich die Konfiguration ändern kann, ohne das Deployment anzufassen.

    Lernziele
    • Du erklärst, wofür eine ConfigMap da ist.
    • Du legst eine ConfigMap mit kubectl an.
    • Du beziehst eine Umgebungsvariable eines Containers aus einer ConfigMap.
    • Du trennst Konfiguration und Deployment.
    Definition of Done
    • kubectl get configmap frontend-config -o yaml zeigt den Schlüssel API_BASE_URL mit der Adresse Deines Backends.
    • Das Deployment des Frontends bezieht API_BASE_URL über configMapKeyRef aus der ConfigMap.
    • Das Frontend zeigt weiterhin die Rezepte vom Backend.
    • Nach einer Änderung an der ConfigMap und einem rollout restart zeigt kubectl exec <pod-name> -- env den neuen Wert.
    • Du hast die Kontrollfragen beantwortet

    Arbeitsschritte

    Eine ConfigMap anlegen

    Diesmal legst Du die Ressource nicht als Datei an, sondern direkt per Befehl. Setz die Adresse Deines Backends ein:

    kubectl create configmap frontend-config --from-literal=API_BASE_URL=http://<backend-host>

    Sieh Dir das Ergebnis an:

    kubectl get configmap frontend-config -o yaml

    Das Deployment des Frontends anpassen

    Ersetze in frontend-deployment.yaml den festen Wert von API_BASE_URL durch einen Verweis auf die ConfigMap:

    env:
  - name: API_BASE_URL
    valueFrom:
      configMapKeyRef:
        name: frontend-config
        key: API_BASE_URL

    Wende das geänderte Deployment an:

    kubectl apply -f frontend-deployment.yaml

    Prüf im Browser, ob das Frontend weiterhin die Rezepte zeigt.

    Die Konfiguration ändern

    Ändere den Wert in der ConfigMap testweise – etwa auf eine Adresse, die es nicht gibt:

    kubectl edit configmap frontend-config

    Hinweis: kubectl edit öffnet die Ressource im Editor der Shell (meist vi: i zum Schreiben, Esc und :wq zum Speichern). Gespeichert wird sie direkt im Cluster.

    Sieh nach, ob der Pod den neuen Wert schon kennt:

    kubectl exec <pod-name> -- env

    Starte das Deployment neu, damit neue Pods mit dem neuen Wert starten:

    kubectl rollout restart deployment/recipes-frontend

    Prüf den Wert im neuen Pod und stell die richtige Adresse danach wieder her.

    Optional: Die ConfigMap als YAML verwalten

    Du hast die ConfigMap per Befehl angelegt. Überleg, wie Du sie stattdessen als eigene Datei frontend-config.yaml beschreiben und mit kubectl apply -f anlegen würdest. Sieh Dir dazu noch einmal die Ausgabe von kubectl get configmap frontend-config -o yaml an: Was davon brauchst Du, was kannst Du weglassen?

    Reflexionsfragen

    • Was gewinnst Du mit einer ConfigMap gegenüber einer Umgebungsvariable, die direkt im Deployment steht?
    • Wann wird eine Änderung an einer ConfigMap wirksam? Muss der Pod neu starten?
    • Für welche Daten ist eine ConfigMap geeignet, und für welche nicht?
