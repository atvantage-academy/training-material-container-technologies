      Was ist OpenShift?

      Red Hat OpenShift ist eine Enterprise-Kubernetes-Plattform. Sie basiert auf Kubernetes und enthält es vollständig, ergänzt es aber um Werkzeuge, Sicherheitsfunktionen und Abstraktionen, die den Betrieb in Unternehmen erleichtern.

      Alles, was Du über Kubernetes lernst, gilt auf OpenShift weiter. Diese Seite zeigt, was dazukommt.

      OpenShift und Kubernetes im Vergleich

      Bereich Kubernetes OpenShift
      CLI kubectl oc – kompatibel mit kubectl, plus OpenShift-eigene Befehle
      Namespaces Namespaces Projects – Namespaces mit zusätzlichen Metadaten und Berechtigungen
      Routing Ingress (braucht einen zusätzlichen Ingress Controller) Routes – integriertes, einfach zu konfigurierendes Routing mit TLS-Terminierung
      Sicherheit RBAC und Pod Security Zusätzlich Security Context Constraints (SCCs), standardmäßig kein Root
      Image Registry Keine integrierte Registry Integrierte Image Registry mit Image Streams
      Operatoren Operatoren möglich OperatorHub – kuratierter Katalog für Operatoren
      Monitoring Selbst einzurichten (etwa Prometheus, Grafana) Integriertes Monitoring und Alerting, vorkonfiguriert
      Logging Selbst einzurichten (etwa EFK-Stack) Integrierte Log-Aggregation
      Web Console Kubernetes Dashboard (einfach) Umfangreiche Web Console mit Entwickler- und Administrator-Perspektive
      Updates Manuell, aufwendig Automatisierte Cluster-Updates, gesteuert über Operatoren
      Support Community Enterprise-Support von Red Hat mit langfristiger Stabilität und Sicherheitspatches

      Klapp die Unterschiede auf, die Dir im Alltag als Entwickler:in begegnen:

      oc und kubectl

      OpenShift bringt das Kommandozeilenwerkzeug oc mit. Es ist vollständig kompatibel mit kubectl – jeder kubectl-Befehl funktioniert auch mit oc. Dazu kommen OpenShift-eigene Befehle wie oc login, oc new-project oder oc expose.

      Beide Werkzeuge nebeneinander: Spickzettel: kubectl und oc.

      Projects und Namespaces

      In Kubernetes heißt die logische Trennung Namespace, in OpenShift Project. Ein Project ist technisch ein Kubernetes-Namespace mit Zusätzen:

      • Anzeigename und Beschreibung – für eine bessere Übersicht
      • Selbstbedienung – Entwickler:innen können eigene Projects anlegen (konfigurierbar)
      • Standardberechtigungen – wer ein Project anlegt, bekommt automatisch Admin-Rechte darauf
      # Project anlegen (OpenShift)
oc new-project mein-projekt --display-name="Mein Projekt"

      # Entspricht in Kubernetes
kubectl create namespace mein-projekt

      Jeder Befehl, der mit Namespaces arbeitet (-n), funktioniert genauso mit Projects.

      Routes und Ingress

      Einer der auffälligsten Unterschiede im Alltag: OpenShift verwendet Routes, um eine Anwendung von außen erreichbar zu machen. Routes bieten:

      • einfache TLS-Terminierung (tls.termination: edge)
      • automatisch erzeugte Hostnamen
      • integriertes Traffic-Management

      Ingress-Ressourcen versteht OpenShift ebenfalls – es setzt sie intern in Routes um.

      Security Context Constraints

      OpenShift erzwingt standardmäßig strengere Sicherheitsregeln als Kubernetes:

      • Container laufen nicht als Root – deshalb nutzen die Übungen Images, die ohne Root-Rechte auskommen (etwa ein unprivilegiertes NGINX).
      • Container bekommen eine zufällige UID aus einem Bereich, der dem Project zugeordnet ist. Sie gehört zur Gruppe root (GID 0).
      • Deshalb fehlen oft Schreibrechte auf Verzeichnisse im Image, die einem festen Benutzer gehören. Ein Image, das auf OpenShift laufen soll, gibt seine Arbeitsverzeichnisse der Gruppe 0 frei.
      Operatoren

      Operatoren sind Kubernetes-native Anwendungen, die die Verwaltung komplexer Anwendungen automatisieren. Sie kapseln anwendungsspezifisches Wissen und bewährte Vorgehensweisen – Bereitstellung, Konfiguration, Skalierung und Lebenszyklus.

      OpenShift stellt mit dem OperatorHub einen kuratierten Katalog bereit, aus dem Operatoren direkt installiert werden können. Auch die Plattform selbst wird über Operatoren betrieben und aktualisiert.

      Web Console

      OpenShift hat eine umfangreiche Web Console mit zwei Blickwinkeln: einer Entwickler-Perspektive (Anwendungen, Topologie, Logs) und einer Administrator-Perspektive (Cluster, Knoten, Berechtigungen).

      Im Kurs arbeitest Du ausschließlich auf der Kommandozeile. Alles, was die Web Console zeigt, liefert auch oc – und die Befehle laufen anschließend auf jedem Cluster gleich.

      Container-Runtime

      Seit Version 4 verwendet OpenShift CRI-O als Container-Runtime statt der Docker-Engine früherer Versionen. CRI-O ist eine schlanke, stabile Laufzeitumgebung, die eigens für Kubernetes entwickelt wurde und sich auf die sichere, zuverlässige Ausführung von Containern konzentriert.

      Hochverfügbarkeit und Fehlertoleranz

      OpenShift nutzt die Mechanismen von Kubernetes und baut sie aus:

      • ReplicaSets und Pod-Autoskalierung für die Verfügbarkeit der Anwendung
      • mehrere Control-Plane-Knoten für Redundanz auf Ebene der Control Plane
      • automatisierte Rolling Updates für möglichst kurze Ausfallzeiten
      • Failover beim Ausfall einzelner Knoten

      Wo OpenShift läuft

      Public Cloud (managed)

      OpenShift Cloud Services – eine schlüsselfertige Plattform, die Red Hat und der Cloud-Anbieter gemeinsam betreiben:

      • ROSA – Red Hat OpenShift on AWS
      • ARO – Azure Red Hat OpenShift
      • Red Hat OpenShift on IBM Cloud

      Vorteile: kein eigener Betrieb, automatische Updates, SLA.

      Privat / On-Premises

      Red Hat OpenShift Platform Plus – selbst betrieben:

      • Bare Metal – direkt auf eigener Hardware
      • VMware vSphere – auf virtualisierter Infrastruktur
      • Private Cloud (etwa OpenStack)
      • Edge – für verteilte Standorte

      Vorteile: volle Kontrolle, Datenhoheit, Compliance.

      Lokal zum Lernen

      Red Hat OpenShift Local (früher CodeReady Containers, CRC):

      • ein vollständiger OpenShift-Cluster auf einem einzigen Knoten
      • läuft auf dem eigenen Rechner (Linux, macOS, Windows)
      • für Lernen und Entwicklung, nicht für die Produktion
      • kostenlos über das Red Hat Developer-Programm
      OpenShift Local starten – die Befehle 
      # Einmalig einrichten
crc setup

      # Den lokalen Cluster starten
crc start

      # Das passende oc in den Suchpfad der Shell holen
eval $(crc oc-env)

      # Als Entwickler:in anmelden
oc login -u developer https://api.crc.testing:6443
