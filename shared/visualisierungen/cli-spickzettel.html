    Spickzettel: kubectl und oc

    kubectl ist das offizielle Kommandozeilenwerkzeug für Kubernetes. oc ist das Werkzeug für OpenShift und vollständig kompatibel mit kubectl: Jeder kubectl-Befehl funktioniert auch mit oc. Dazu kommen OpenShift-eigene Befehle wie oc login, oc new-project und oc expose service.

    So liest Du die Tabellen: links kubectl, rechts oc. Wo beide gleich lauten, steht der Befehl trotzdem zweimal da – Du sollst nicht umdenken müssen. Wo es kein Gegenstück gibt, steht ein „–“. Platzhalter stehen in spitzen Klammern: <pod-name>.

    Verbindung und Kontext

    Was kubectl oc
    Am Cluster anmelden – (die Zugangsdaten stehen in der kubeconfig, ~/.kube/config) oc login https://api.<cluster>:6443
    Aktuellen Kontext anzeigen kubectl config current-context oc config current-context
    Verfügbare Kontexte anzeigen kubectl config get-contexts oc config get-contexts
    Kontext wechseln kubectl config use-context <context-name> oc config use-context <context-name>
    Aktuellen Benutzer anzeigen kubectl auth whoami oc whoami

    Hinweis: oc login schreibt die Zugangsdaten in dieselbe kubeconfig, die kubectl und helm lesen. Nach dem Login funktionieren alle drei Werkzeuge.

    Projects und Namespaces

    Was kubectl oc
    Anlegen kubectl create namespace mein-projekt oc new-project mein-projekt --display-name="Mein Projekt"
    Als Standard setzen kubectl config set-context --current --namespace=mein-projekt oc project mein-projekt
    Aktuellen anzeigen kubectl config view --minify -o jsonpath='{..namespace}' oc project
    Alle anzeigen kubectl get namespaces oc get projects
    Einen Befehl in einem anderen ausführen kubectl get pods -n <namespace> oc get pods -n <namespace>

    Ressourcen anzeigen

    Was kubectl oc
    Pods anzeigen kubectl get pods oc get pods
    … mit Knoten und IP kubectl get pods -o wide oc get pods -o wide
    … live verfolgen kubectl get pods -w oc get pods -w
    Die gängigen Ressourcen auf einmal kubectl get all oc get all
    Deployments, Services, ConfigMaps, Secrets kubectl get deployments,services,configmaps,secrets oc get deployments,services,configmaps,secrets
    Zugang von außen kubectl get ingress oc get routes
    Pods in allen Namespaces kubectl get pods -A oc get pods -A
    Eine Ressource als YAML kubectl get deployment <name> -o yaml oc get deployment <name> -o yaml
    Alle Ressourcentypen des Clusters kubectl api-resources oc api-resources
    Felder einer Ressource erklären kubectl explain deployment.spec oc explain deployment.spec

    Hinweis: -A ist die Kurzform von --all-namespaces. In einem Schulungscluster darfst Du womöglich nicht in alle Namespaces schauen – dann meldet der Befehl Forbidden. Das ist eine Frage der Rechte, kein Fehler im Befehl.

    Ressourcen anlegen, ändern und löschen

    Was kubectl oc
    Aus einer YAML-Datei anlegen oder aktualisieren kubectl apply -f deployment.yaml oc apply -f deployment.yaml
    Alle YAML-Dateien eines Ordners anwenden kubectl apply -f ./manifeste/ oc apply -f ./manifeste/
    Ein Deployment direkt anlegen kubectl create deployment mein-app --image=<image>:<tag> oc create deployment mein-app --image=<image>:<tag>
    Im Editor bearbeiten kubectl edit deployment <name> oc edit deployment <name>
    Einen Pod löschen kubectl delete pod <pod-name> oc delete pod <pod-name>
    Alles aus einer Datei löschen kubectl delete -f deployment.yaml oc delete -f deployment.yaml
    Alle Pods im Namespace löschen kubectl delete pods --all oc delete pods --all

    YAML erzeugen lassen statt von Hand schreiben

    --dry-run=client -o yaml legt nichts an, sondern gibt das YAML aus, das angelegt würde. Mit > landet es in einer Datei, die Du anpassen und dann mit apply anwenden kannst.

    Was kubectl oc
    Deployment-YAML erzeugen kubectl create deployment mein-app --image=<image>:<tag> --dry-run=client -o yaml > deployment.yaml oc create deployment mein-app --image=<image>:<tag> --dry-run=client -o yaml > deployment.yaml
    Service-YAML erzeugen kubectl expose deployment mein-app --port=8080 --dry-run=client -o yaml > service.yaml oc expose deployment mein-app --port=8080 --dry-run=client -o yaml > service.yaml

    Details und Debugging

    Was kubectl oc
    Details mit Events und Conditions kubectl describe pod <pod-name> oc describe pod <pod-name>
    … eines Deployments kubectl describe deployment <name> oc describe deployment <name>
    Ereignisse im Namespace, zeitlich sortiert kubectl get events --sort-by=.lastTimestamp oc get events --sort-by=.lastTimestamp
    Logs eines Pods kubectl logs <pod-name> oc logs <pod-name>
    … live verfolgen kubectl logs <pod-name> -f oc logs <pod-name> -f
    … eines bestimmten Containers im Pod kubectl logs <pod-name> -c <container> oc logs <pod-name> -c <container>
    … des vorigen Containers (nach einem Neustart) kubectl logs <pod-name> --previous oc logs <pod-name> --previous
    Shell in einem laufenden Pod öffnen kubectl exec -it <pod-name> -- /bin/sh oc exec -it <pod-name> -- /bin/sh
    Einen Befehl im Pod ausführen (etwa die Umgebungsvariablen) kubectl exec <pod-name> -- env oc exec <pod-name> -- env
    Port-Weiterleitung auf den eigenen Rechner kubectl port-forward <pod-name> 8080:8080 oc port-forward <pod-name> 8080:8080
    Debug-Shell in einem Pod, der nicht startet – oc debug <pod-name>

    Deployments verwalten

    Was kubectl oc
    Skalieren kubectl scale deployment <name> --replicas=3 oc scale deployment <name> --replicas=3
    Alle Pods neu starten (Rolling Restart) kubectl rollout restart deployment <name> oc rollout restart deployment <name>
    Rollout verfolgen kubectl rollout status deployment <name> oc rollout status deployment <name>
    Rollout-Historie anzeigen kubectl rollout history deployment <name> oc rollout history deployment <name>
    Zur vorigen Version zurück kubectl rollout undo deployment <name> oc rollout undo deployment <name>
    Image eines Containers tauschen kubectl set image deployment/<name> <container>=<image>:<tag> oc set image deployment/<name> <container>=<image>:<tag>

    ConfigMaps und Secrets

    Was kubectl oc
    ConfigMap aus Werten kubectl create configmap meine-config --from-literal=KEY=value oc create configmap meine-config --from-literal=KEY=value
    ConfigMap aus einer Datei kubectl create configmap meine-config --from-file=config.properties oc create configmap meine-config --from-file=config.properties
    Secret aus Werten kubectl create secret generic mein-secret --from-literal=PASSWORD=geheim oc create secret generic mein-secret --from-literal=PASSWORD=geheim
    Pull Secret für eine Registry kubectl create secret docker-registry mein-pull-secret --docker-server=docker.io --docker-username=<user> --docker-password=<token> oc create secret docker-registry mein-pull-secret --docker-server=docker.io --docker-username=<user> --docker-password=<token>
    Einen Wert eines Secrets lesen kubectl get secret mein-secret -o jsonpath='{.data.PASSWORD}' | base64 -d oc extract secret/mein-secret --keys=PASSWORD --to=-
    Alle Variablen eines Deployments anzeigen kubectl set env deployment/<name> --list oc set env deployment/<name> --list

    Hinweis: Base64 ist keine Verschlüsselung. Wer ein Secret lesen darf, kennt den Wert. Warum das so ist und was dagegen hilft: Sind Secrets sicher?

    Netzwerk: Service, Ingress, Route

    Was kubectl oc
    Service für ein Deployment anlegen kubectl expose deployment <name> --port=8080 oc expose deployment <name> --port=8080
    Von außen erreichbar machen kubectl create ingress <name> --rule="<host>/*=<service>:8080" oc expose service <service>
    … mit TLS (HTTPS) Ingress mit tls-Abschnitt und Zertifikat oc create route edge <name> --service=<service>
    Adressen anzeigen kubectl get ingress oc get routes
    Endpunkte eines Services (die Pods dahinter) kubectl get endpoints <service> oc get endpoints <service>

    Nützliche Optionen

    Option Wirkung
    -n <namespace> Namespace bzw. Project angeben
    -o yaml / -o json Ausgabe als YAML bzw. JSON
    -o wide Erweiterte Ausgabe (etwa Knoten, IP)
    -o jsonpath='{...}' Bestimmte Felder herausziehen
    -w / --watch Live aktualisieren
    -l app=mein-app Nach Label filtern
    --dry-run=client -o yaml YAML erzeugen, ohne es anzuwenden
