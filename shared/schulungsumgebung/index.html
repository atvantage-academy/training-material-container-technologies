Die Schulungsumgebung nutzen

Für die Übungen brauchst Du eine Container-Laufzeitumgebung. Es gibt zwei Wege dorthin, und welcher für Deinen Kurs gilt, sagt Dir Dein Trainer am ersten Tag.

Die Anleitungen im Kurs sind Kommandozeile. Das ist keine Sparmaßnahme, sondern der kleinste gemeinsame Nenner: Die bereitgestellte Umgebung hat keine grafische Oberfläche, und die Befehle, die Du hier lernst, laufen anschließend auf jedem Rechner gleich – lokal, auf dem Server, in einer Build-Pipeline. Eine Oberfläche kann Dir das nicht abnehmen.

Zwei Wege zur Laufzeitumgebung

Weg A: lokal auf Deinem Rechner

Du installierst Docker selbst und arbeitest auf Deinem eigenen Gerät.

   
Windows Docker Desktop, bedient aus der Git Bash (nicht aus PowerShell oder cmd – die Anleitungen im Kurs setzen eine Bash-Zeile voraus)
macOS / Linux Docker Desktop bzw. Docker Engine, bedient aus dem Terminal
Prüfen docker version gibt Client und Server aus. Fehlt der Server-Teil, läuft der Docker-Dienst nicht.

Hinweis: Docker Desktop bringt eine grafische Oberfläche mit. Du darfst sie gern benutzen, um Dir Dinge anzusehen – die Übungen führst Du trotzdem auf der Kommandozeile durch, sonst fehlt Dir am zweiten Tag das Handwerkszeug.

Weg B: die bereitgestellte Umgebung im Browser

Du bekommst einen Zugang zu einer zentralen Umgebung und arbeitest dort in einer Shell im Browser. Du installierst nichts, Du brauchst keine lokalen Rechte, und alle Teilnehmenden arbeiten auf demselben Stand.

   
Betriebssystem Linux
Zugang Web-Adresse plus persönliche Zugangsdaten – beides bekommst Du vom Trainer
Oberfläche keine. Es gibt eine Shell, sonst nichts.
Kommando docker – dieselben Befehle wie lokal
Zwischenablage Kopieren und Einfügen in der Browser-Shell verhält sich je nach Browser anders. Probiere es zu Beginn einmal aus, bevor Du einen langen Befehl tippst.

Was Du hier nicht findest, sind die konkreten Adressen und Zugangsdaten. Sie sind kursspezifisch und werden nicht in der Unterlage veröffentlicht. Frag Deinen Trainer.

Was in beiden Fällen gilt

  • localhost ist nicht überall dasselbe. Startest Du lokal einen Container mit -p 8080:80, erreichst Du ihn unter http://localhost:8080. In der bereitgestellten Umgebung läuft der Container auf einem anderen Rechner als Dein Browser – wie Du dort an den Port kommst, sagt Dir der Trainer.
  • Dein Arbeitsverzeichnis ist nicht dauerhaft. Lege Dateien, die Du behalten willst, in einem Git-Repository ab und pushe sie.
  • Du brauchst ein Konto bei einer Container-Registry, um eigene Images zu veröffentlichen. Welche das ist, sagt der Kurs.

Die Befehle, mit denen Du auskommst

Du musst kein Linux-Profi sein. Über den ganzen Kurs hinweg brauchst Du neben docker nur diese Handvoll Befehle:

Befehl Wofür
pwd Wo bin ich gerade?
ls Was liegt hier?
cd <ordner> In einen Ordner wechseln (cd .. geht eine Ebene zurück)
mkdir <ordner> Ordner anlegen
cat <datei> Datei anzeigen
echo "Text" > datei.txt Datei mit Inhalt anlegen (>> hängt an, statt zu überschreiben)
nano <datei> Datei bearbeiten (Speichern: Strg+O, Beenden: Strg+X)
curl http://localhost:8080 Eine Web-Adresse von der Kommandozeile abrufen

Hinweis: Mit der Tabulatortaste vervollständigt die Shell Datei- und Ordnernamen, mit der Pfeiltaste nach oben holst Du den letzten Befehl zurück. Beides spart im Kurs mehr Zeit als jede Abkürzung.

Noch offen

Diese Seite ist noch nicht vollständig. Es fehlen die konkreten Angaben zur bereitgestellten Umgebung: Einstiegsadresse, Anmeldeverfahren, Namensschema der Arbeitsbereiche, der Weg zu einem veröffentlichten Port und die verwendete Registry. Sie werden ergänzt, sobald sie vorliegen.
