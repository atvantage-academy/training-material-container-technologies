    Minikube für die Schulung einrichten

    User Story

    Als Teilnehmer:in des Kubernetes-Kurses möchte ich einen Cluster auf meinem eigenen Rechner, damit ich die Übungen ohne bereitgestellte Umgebung durcharbeiten kann.

    Definition of Done
    • kubectl get nodes zeigt den Knoten minikube mit dem Status Ready.
    • kubectl get pods -n ingress-nginx zeigt den Pod des Ingress Controllers mit dem Status Running.
    • kubectl config view --minify --output 'jsonpath={..namespace}' gibt schulung aus.
    • helm version gibt eine Versionsnummer aus.

    Diese Anleitung richtet einen lokalen Kubernetes-Cluster mit Minikube ein und bereitet ihn für die Übungen vor. Arbeite sie vor dem ersten Kurstag durch – ein Download, der in der Schulung hängt, kostet die ganze Gruppe Zeit.

    Hinweis: Unter Windows gibst Du alle Befehle in der Git Bash ein, nicht in PowerShell oder cmd. Unter macOS und Linux nimmst Du das Terminal.

    Arbeitsschritte

    Prüfen, ob Docker läuft

    Minikube startet den Cluster in einem Docker-Container. Docker muss also laufen – eingerichtet wie im Docker-Kurs.

    # Gibt Client UND Server aus, wenn Docker läuft
docker version

    Fehlt in der Ausgabe der Teil Server, starte zuerst Docker Desktop bzw. den Docker-Dienst.

    Minikube installieren

    Installiere Minikube mit dem Paketmanager Deines Betriebssystems.

    macOS 
    brew install minikube
    Windows (Git Bash) 
    winget install Kubernetes.minikube

    Arbeitest Du mit Chocolatey, geht auch choco install minikube (in einer Shell mit Administratorrechten). Alternativ gibt es einen Installer.

    Linux 
    # Das Programm herunterladen
curl -LO https://storage.googleapis.com/minikube/releases/latest/minikube-linux-amd64

    # Und in den Suchpfad installieren
sudo install minikube-linux-amd64 /usr/local/bin/minikube

    Hinweis: Unter Windows findet die Git Bash ein frisch installiertes Programm oft erst, wenn Du sie neu öffnest.

    kubectl installieren

    Falls kubectl noch nicht installiert ist:

    macOS 
    brew install kubectl
    Windows (Git Bash) 
    winget install Kubernetes.kubectl

    Mit Chocolatey: choco install kubernetes-cli.

    Linux 
    sudo snap install kubectl --classic

    Ohne Snap: die Anleitung kubectl unter Linux installieren.

    # Prüfen, ob kubectl gefunden wird
kubectl version --client

    Helm installieren

    Das letzte Modul des Kurses paketiert die Anwendung mit Helm.

    macOS 
    brew install helm
    Windows (Git Bash) 
    winget install Helm.Helm
    Linux 
    sudo snap install helm --classic

    # Prüfen, ob Helm gefunden wird
helm version

    Minikube starten

    Starte den lokalen Cluster – mit Docker als Grundlage:

    minikube start --driver=docker

    Der erste Start lädt einige Hundert Megabyte herunter und dauert ein paar Minuten.

    Den Cluster prüfen

    # Adresse der Control Plane anzeigen
kubectl cluster-info

    # Die Knoten des Clusters anzeigen – hier genau einer
kubectl get nodes

    minikube start hat kubectl gleich auf den neuen Cluster eingestellt; Du musst Dich nicht anmelden.

    Den Ingress Controller aktivieren

    Für die Übungen brauchst Du einen Ingress Controller – er macht Deine Anwendungen von außen erreichbar. Minikube bringt den NGINX Ingress Controller als Addon mit:

    minikube addons enable ingress

    # Prüfen, ob der Ingress Controller läuft
kubectl get pods -n ingress-nginx

    Warte, bis der Pod ingress-nginx-controller-… den Status Running hat. Die anderen Pods (…-admission-…) enden mit Completed – das ist richtig so.

    Einen Namespace anlegen und als Standard setzen

    Leg einen eigenen Namespace für die Schulung an:

    kubectl create namespace schulung

    Setz ihn als Standard für den gewählten Kontext, damit Du nicht bei jedem Befehl -n schulung angeben musst:

    kubectl config set-context --current --namespace=schulung

    # Prüfen, welcher Namespace eingestellt ist
kubectl config view --minify --output 'jsonpath={..namespace}'

    Die Ausgabe lautet schulung. Ab jetzt arbeiten alle kubectl-Befehle in diesem Namespace.

    Verstehen, wie ein Ingress von außen erreichbar wird

    Das brauchst Du erst in der ersten Übung – lies es jetzt, damit es dort nicht überrascht.

    Ein Ingress in den Übungen trägt einen Hostnamen wie recipes-backend.127.0.0.1.nip.io. Der Dienst nip.io löst jeden solchen Namen auf die darin enthaltene IP-Adresse auf – hier 127.0.0.1, also Deinen eigenen Rechner. Damit Anfragen an 127.0.0.1 beim Ingress Controller im Cluster ankommen, läuft in einem zweiten Terminal der Tunnel:

    minikube tunnel

    Lass dieses Terminal offen, solange Du übst. Der Tunnel fragt beim Start eventuell nach Deinem Passwort, weil er die Ports 80 und 443 belegt.

    Nützliche Befehle

    Befehl Wirkung
    minikube start Cluster starten
    minikube stop Cluster anhalten (der Zustand bleibt erhalten)
    minikube delete Cluster vollständig löschen
    minikube status Zeigen, ob der Cluster läuft
    minikube tunnel Ingress und Services vom Typ LoadBalancer lokal erreichbar machen
    minikube service <name> --url Die URL eines Services anzeigen
    minikube addons list Alle Addons und ihren Zustand anzeigen

    Reflexionsfragen

    Keine – das ist eine Anleitung zum Einrichten, keine Lernübung. Was Minikube von einem echten Cluster unterscheidet, kommt im Kurs zur Sprache.
